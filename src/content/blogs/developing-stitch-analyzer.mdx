# Building Cheats Analyzer: Anti-Cheat Packet Interception

Cheating in competitive Minecraft is a constant cat-and-mouse game. Basic file checkers don't work anymore because cheat clients inject DLLs directly into game memory without touching files on disk.

To solve this for tournament servers, I built **Cheats Analyzer** using two connected parts: a desktop client and a server plugin.

---

## 1. Why two parts?

- **Client checks alone aren't enough**: Players can modify clients or disguise background processes.
- **Server checks alone can produce false flags**: Bad internet latency or lag spikes can make normal players look like they're speed-hacking.

By using both, the client confirms that the game memory is unmodified, and the server plugin validates actual combat and movement packets in real time.

## 2. Server-side packet listening

To monitor player clicks, movement vectors, and hit registration without adding server lag, I hooked directly into the Netty channel pipeline:

```java
public class PacketHandler extends ChannelDuplexHandler {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) throws Exception {
        if (msg instanceof PacketPlayInFlying) {
            // Check player velocity and coordinate offsets
        }
        super.channelRead(ctx, msg);
    }
}
```

The plugin checks click speeds, reach distance, and unnatural velocity deltas. If suspicious behavior is detected, it logs the incident and alerts tournament staff.

## 3. What I learned

- **Never block the main server tick**: Packet analysis has to happen asynchronously or in Netty's event loop so the game stays locked at 20 TPS.
- **Clear evidence over instant auto-bans**: Giving admins recorded packet logs and click graphs prevents accidental bans from network hiccups.
